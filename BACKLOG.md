# Backlog

Остатки дизайна после v0-спеки (README.md + env.example.yml, 2026-10-27).
Каждый пункт — вопрос, а не обещание.

1. **CI-валидатор (`--check`).** Локальный хук обходится через `git commit --no-verify`,
   а серверные мержи (кнопка Merge PR) pre-commit хуки не запускают вовсе. Семантика
   как у auto-version-hook: 0 — норма, 1 — хук заблокировал бы, 2 — проблемы конфига.
   Плюс готовые джобы для GitLab CI и GitHub Actions.

2. **Строгость сверки рабочей копии с индексом.** Сейчас рассинхрон (изменили `env.yml`
   или чекаут сабмодуля, но не сделали `git add`) — предупреждение. Не окажется ли,
   что его все игнорируют и надо блокировать? Решить после реального использования.

3. **`--sync` — одна команда на все сабмодули.** Сообщение ошибки уже несёт готовую
   команду починки; флаг, который переключает все сабмодули на закреплённые коммиты
   и делает `git add`, — просто сахар. Взять, если руками надоест.

4. **`on-demand` режим pre-push.** Вместо блокировки — самому запушить сабмодуль,
   как встроенному `git push --recurse-submodules=on-demand`. Только opt-in флагом:
   ломает принцип «хук ничего не меняет, только читает».

5. **Автобамп пина роботом.** Renovate (regex manager) и Dependabot (экосистема
   `gitsubmodule`) умеют открывать PR с обновлением gitlink; натравить на
   `commit_sha` в env.yml — робот делает бамп, хук гарантирует комплектность
   (gitlink + конфиг едут одним PR).
